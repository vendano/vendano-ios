# Vendano iOS

### Simple, contact-based ADA for everyone

Vendano is an open-source iOS wallet that lets anyone **send and receive ADA (and native tokens) using a phone number or e-mail address** instead of a 58-character address.

The goal is to make Cardano transactions feel as familiar as texting: no arcane jargon and an interface that guides first-time users in plain language.

> **Why there’s room for Vendano**
> Most Cardano wallets excel at power-user features (staking dashboards, hardware-wallet pairing, multi-asset portfolios), yet still ask newcomers to master new concepts before they can move a single coin. Vendano's mission focuses on **on-ramp simplicity**: features such as verified contacts, one-tap transfers, and automatic on-chain “claim” flows for recipients who haven’t installed the app yet.

### Repository Overview

**vendano-ios** is the open-source SwiftUI codebase for the production Vendano wallet distributed through Apple's App Store. The current production release requires iOS 18 or later and iPadOS 18 or later.

End users install the signed production application directly from the App Store; they do not clone this repository, open Xcode, or provide developer credentials. Info.plist, GoogleService-Info.plist, Blockfrost credentials, Apple signing material, and entitlements are intentionally excluded from public source control because they contain environment-specific configuration or secrets.

Developers compiling an independent fork must provide their own service configuration and signing identity. This separation between the signed production binary and public source code is standard mobile release practice.

### Security and privacy notes

Vendano is a self-custody wallet. Recovery words and private keys remain under the user’s control; Vendano cannot recover a lost recovery phrase.

- **Wallet creation:** new 12-, 15-, and 24-word recovery phrases use BIP-39. Entropy is generated by Apple’s cryptographically secure `SecRandomCopyBytes` facility through the project’s pinned cryptographic dependencies. Vendano does not implement its own random-number generator.
- **Transaction signing:** key derivation and Cardano transaction signing are delegated to pinned Cardano.swift/cardano-serialization-lib dependencies. Vendano does not implement its own Ed25519 signing or nonce algorithm.
- **On-device storage:** recovery words are stored in the iOS Keychain using its when-unlocked protection. Transaction submission requests device-owner authentication—Face ID, Touch ID, or the device passcode—when supported. The current Keychain item is not configured to require biometric authentication every time it is read.
- **Contact discovery:** Vendano does not upload the user’s address book. Verified phone numbers and email addresses are retained in the authenticated user’s private account record. Public discovery records contain normalized SHA-256 hashes. These hashes reduce direct exposure but are not encryption or anonymity and may be susceptible to guessing.
- **Remote services:** Firebase provides authentication and application data services, while Blockfrost provides Cardano network access. Wallet addresses, transaction identifiers, amounts, and other blockchain activity are public by the nature of Cardano.
- **Sensitive information:** recovery phrases and private keys must never be placed in logs, analytics, screenshots, issues, pull requests, or support messages. Production credentials and Apple signing material are excluded from the public repository.
- **Audit status:** the public implementation can be reviewed, but Vendano has not undergone an independent third-party security audit. Open source should not be interpreted as a security warranty.

See [SECURITY.md](SECURITY.md) for implementation details, limitations, and private vulnerability reporting.

### Review and contributing

Contributions are welcome through pull requests.

- Read [CONTRIBUTING.md](CONTRIBUTING.md) before submitting a change.
- Do not report suspected vulnerabilities through a public issue or pull request. Follow the private process in [SECURITY.md](SECURITY.md).
- Changes involving wallet generation, key storage, authentication, transaction construction, signing, networking, or dependencies require focused security review and reproducible test results.
- Do not introduce custom cryptographic algorithms or random-number generation.
- User-facing changes must update every supported localization and preserve formatting placeholders. Security warnings, recovery instructions, and transaction language require human review rather than unreviewed machine translation.
- Never commit production credentials, Firebase configuration, Blockfrost credentials, Apple signing material, recovery phrases, private keys, or real user data.
